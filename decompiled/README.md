# Decompiled output — Granny 2 Rework (Unreal Engine)

Generated automatically by `.github/workflows/decompile.yml`.

## What's here
- `Assets/` — every file extracted from the game's `.pak` (the whole game content)
- `Binaries/` — game executables + DLLs for local analysis (Ghidra/IDA/x64dbg)
- `scripts/` — decompiled C pseudo-code of the game's code (produced by Ghidra; present only when
  the workflow was run with the "ghidra_decompile" input enabled). One `.c` file per function.
- `AssetList.txt` — full inventory of every extracted file
- `Maps.txt` — list of level/map files (`.umap`)
- `Blueprints_Scripts.txt` — list of Blueprint assets (empty: this game has no Blueprints)
- `Animations.txt` — list of animation-related assets

## Notes
- This is an **Unreal Engine** build (not Unity): there is no managed C# to decompile.
- The game's logic is **native C++** compiled into `Binaries/G2RRecreated-Win64-Shipping.exe`.
  `scripts/` contains Ghidra's decompiled pseudo-C of that binary (assembly-derived, so it is
  low-level and not a faithful recreation of the original source).
- The extracted `.uasset`/`.uexp` files contain the level/gameplay data. To view them, open with
  **uAssetGUI**, **FModel**, or load them into the Unreal Editor. Maps are `.umap` files.
- UnrealPak / repak was used for extraction: run `repak unpack <pak> -o <dir>` to re-extract.
